# NFL dashboard daily update: the task's instructions

This file is the instructions for the scheduled task **NFL dashboard daily update**. The task's own
prompt only attaches the repo, lists the web addresses it may fetch, and says to read this file and
follow it. To change what the task does, change this file in a pull request; CONVENTIONS.md ("The
daily task") says when the task's prompt has to change too. Everything below the line is written to
the run.

---

Daily update for my NFL Matchup Dashboard — https://rhyman7.github.io/nfl/ (repo: github.com/rhyman7/nfl, branch main, served by GitHub Pages from the repo root).

**This is the daily run (every day at 10:50 AM ET).** It replaces the old separate Wednesday, Friday and weekend tasks. On the first run after a week's last game (usually Tuesday, after Monday Night Football) it is the **new-week update**: the data moves to the next week and that week's opening lines are set. On every other day it is a **refresh**: stats stay on the same through-week, and referee assignments and lines are refreshed. Step 2 says which one today is.

**Web addresses (read this before any WebFetch).** WebFetch only opens an address that appears word for word in this conversation: in the task's prompt or in a WebSearch/WebFetch result. An address you build from a pattern is refused (PROVENANCE_REQUIRED) or waits for an approval nobody is around to give, and the run stalls. So copy the addresses exactly as written (the three this task fetches are repeated in the task's prompt for that reason), and don't hand addresses to subagents to fetch. If WebFetch or WebSearch isn't in your tool list, load them with ToolSearch (query select:WebFetch,WebSearch) before deciding they're missing.

**Injury designations come only from ESPN's injury report, and this task doesn't handle them.** Since PR #15 (Oct 25, 2026) the repo's **Fetch injuries** Action (`.github/workflows/fetch-injuries.yml`, every 3 hours) runs `scripts/fetch_espn_injuries.py`, which reads ESPN's per-team injury lists and writes `data/injuries.json`; `common.js` reads that file in the viewer's browser and tags players O, D, Q, IR, PUP or SUSP (falling back to ESPN's league feed if the file is missing or over 2 days old). This task does not download, build, edit, commit or check any injury data: no nflverse injury file, no injury tags in `data.json`, and never touch `data/injuries.json`. ESPN can't be reached from the workspace, so don't try to read it. Injury tags showing in the headless test (from `data/injuries.json`) are expected; so is their absence.

**The run log lives in the repo.** `UPDATE_LOG.md` at the repo root (newest entries first) is this task's record: each run adds an entry (step 7) and commits it with the data. It used to be a Claude project doc (`claude/weekly-update-log.md`); don't read or write that doc any more.

## Goal
Refresh `data/data.json` with current 2026 NFL regular-season stats and this week's schedule, and push it to main so the live site updates. The site has nine pages: `index.html` (this week's matchups), `how-to-read.html` (How to Read Matchups), `epa.html` (EPA), `epa-explained.html` (EPA Explained), `edges.html` (Weekly Edges: game board and prop matchups), `matchup.html?game=<id>` (one game in detail), `print.html` (prints every matchup), `compare.html` (pick any two teams) and `ratings.html` (SoS/SRS explained); they share `common.js`, `style.css` and `teamcolors.js`, plus the page scripts. Do not change any of the site's HTML, JS or CSS unless it's missing or broken (see "If the site is missing"). (Live scores, box scores, the current ESPN line and the kickoff forecast are fetched by the viewer's browser at page load, and injury tags come from `data/injuries.json` via its own Action; this task never touches them.) Every page reads `data/data.json`, so the JSON shape below must stay exactly the same. The week strip in the top bar also reads `data/season.json` and `data/weeks/<N>.json`; the build script writes those on every run, so don't edit them by hand. The EPA page reads `data/epa.json`, which the build script also writes on every run from the play-by-play file (via `scripts/epa_ratings.py`); don't edit it by hand either.

**Intentional site state (don't treat as broken):** the October 2026 redesign (week board, scorebug header, team-color blocks, Head to Head rank bars, Archivo type), the week strip, team game lists, the EPA pages, the matchup and EPA PDFs built by a GitHub Action after each push, and the ESPN injury tags (`data/injuries.json` from the Fetch injuries Action, PR #15, whose "Update injuries (ESPN)" commits land on main between runs). The DraftKings/FanDuel sportsbook buttons and prop-line columns were removed on purpose (PR #10, Oct 2026); the prop check tool in the game-log panel and the five prop matchup tables on Weekly Edges are still there.

**Current season only.** Every number on the site must come from the current NFL season (2026 now; if you're running in a later year, use the season in progress). Build `data.json` from scratch each run; never merge with, carry over or average in anything from a previous season. If the published file is from an earlier season, replace it entirely. Only include players who have played for that team this season. Two deliberate exceptions, both handled by the build script: referee tendencies use this season plus the three before it (labeled on the site), and each schedule game's `lineOpen` (the line from this week's first update) is kept from the published file when it's the same season and week, so line movement is measured from the week's first build.

nflverse uses abbreviations; the site uses full names exactly as Pro-Football-Reference writes them (e.g. "Arizona Cardinals", "Los Angeles Rams" for LA, "Los Angeles Chargers" for LAC, "Las Vegas Raiders" for LV, "Washington Commanders" for WAS). ## data.json shape (must match exactly)
```
{
  "generatedAt": ISO-8601 UTC timestamp,
  "season": 2026, "throughWeek": last fully completed week,
  "schedule": { "week", "byes": [full names], "games": [ { "id" (nflverse game_id), "gameday", "weekday", "gametime" (ET, "HH:MM"),
                "away", "home" (full names), "awayScore", "homeScore" (null until played), "spread" (positive = home favored),
                "total", "stadium", "roof", "divisional", "awayQb", "homeQb", "referee" (null until assigned),
                "awayRest", "homeRest" (days), "espnId" (ESPN game id, string), "start" (kickoff UTC, "YYYY-MM-DDTHH:MMZ"),
                "neutral" (bool), "city", "lat", "lon", "indoor" (bool; from STADIUMS),
                "lineOpen": { "spread", "total", "at" (date of the week's first update) } } ] },   // the first week not fully played
  "teamNames": [sorted full team names],
  "gameLogs": { "<ABBR>|<player_id>": [ { "w", "opp", "at", "res", "cmp", "att", "pYds", "pTd", "int", "car", "rYds", "rTd",
                "tgt", "rec", "recYds", "recTd", "fl", "fp" } ] },   // one entry per game; zero stats are left out
  "injuryWeek": null (injury tags come from data/injuries.json, ESPN),
  "referees": { "<name>": { "g", "ppg", "o", "u", "p", "homeWinPct", "cur" } },   // cur = games this season
  "refereeSeasons": "2023–2026",
  "leagueAverage": { "rushTdG", "passTdG", "ppg" },          // mean over 32 offenses, 1 decimal
  "gaugeRanges": { "offRushYdsG", "offPassYdsG", "defRushYdsG", "defPassYdsG" },  // each {min: 0, max: ceil((leagueMax + 5% of (max-min)) / 5) * 5}
  "teams": { "<Full Name>": {
    "team": "<Full Name>", "abbr": nflverse abbreviation,
    "record":  { "w", "l", "t", "sos", "srs", "osrs", "dsrs" },          // 1 decimal for ratings
    "offense": { "ppg", "rushYdsG", "rushYdsGRank", "rushTdG", "passYdsG", "passYdsGRank", "passTdG", "int" },
    "defense": { "papg", "rushYdsG", "rushYdsGRank", "rushTdG", "passYdsG", "passYdsGRank", "passTdG", "int" },
    "passing":   [ { "player", "ydsG", "td", "int", "pos", "log" } ],               // top 6 by yds/G
    "rushing":   [ { "player", "ydsG", "td", "ya", "ag", "pos", "log" } ],          // top 6 by yds/G
    "receiving": [ { "player", "ydsG", "td", "yr", "rec", "pos", "log" } ],         // top 7 by yds/G
    "defVsPosition": { "rb", "recRb", "te", "wr" },                   // each { "rank", "yds", "td" }
    "betting": { "ats", "fav", "dog", "home", "away": { "w", "l", "p" }, "ou": { "o", "u", "p" },
                 "games": [ { "w", "opp", "at", "line", "score", "ats", "total", "ou" } ] },
    "eff": { "off", "def": { "epa", "sr", "passEpa", "rushEpa", "plays", "epaRank", "srRank" } }
  } }
}
```
The build script is the source of truth for the shape: it also writes any keys added since this was written (for example each team's `games` list). Don't remove them.

## How each number is defined
- All team stats are **per game** over games that team has played (bye weeks don't count). Yards and PPG to 1 decimal; TD/G and Int/G to 2 decimals.
- Offense: ppg = points scored/G (games.csv); rushYdsG, rushTdG, passYdsG, passTdG from team stats; int = interceptions thrown/G.
- Defense: papg = points allowed/G; rush/pass yards and TDs allowed/G = the opponents' offensive numbers in games against this team; int = interceptions made/G (def_interceptions).
- Ranks: offense rank 1 = most yards/G; defense rank 1 = fewest yards/G allowed. Ties share the lower number.
- Strength ratings (record.sos/srs/osrs/dsrs): from PFR's standings when that page loads, otherwise computed by the build from this season's final scores (`scripts/srs.py`, PFR's method). 1 decimal.
- Player tables: per-game values over games the player appeared in for that team — ydsG, td (TD/G), int (Int/G), ya (yards per carry), ag (carries/G), yr (yards per reception), rec (receptions/G). Passing = players with pass attempts; rushing = players with carries; receiving = players with targets. Sort by ydsG descending. Use `player_display_name`. If a player changed teams, only count games for this team. `pos` is the player's nflverse position (QB, RB, WR, TE…); `log` is the key of that player's entry in `gameLogs`. There is no `inj` key: the site adds injury tags from `data/injuries.json` (ESPN) in the browser, matching players by name and team.
- gameLogs (drives the player hover tooltip, click panel and prop check): one entry per game the player played for that team, in week order. w = week, opp = opponent abbreviation, at = true if that team was the away team (false for home and neutral), res = result like "W 24-17", then that game's passing (cmp, att, pYds, pTd, int), rushing (car, rYds, rTd) and receiving (tgt, rec, recYds, recTd) stats, fl = fumbles lost, fp = full-PPR fantasy points (nflverse `fantasy_points_ppr`, 1 decimal).
- betting (Betting Trends section): from each completed game's closing `spread_line` and `total_line` in games.csv. A team's `line` is its own spread (negative = favored; home line = −spread_line, away = +spread_line). ATS result per game: W if points for − points against + line > 0, L if < 0, P if 0. fav = games with line < 0, dog = line > 0, home/away skip neutral-site games. ou: O if total points > total_line, U if <, P if equal. games lists every game in week order with score as "us-them".
- eff (Head to Head and Weekly Edges): from play-by-play, regular season through throughWeek, plays with pass == 1 or rush == 1 and a non-missing EPA. epa = mean EPA per play (3 decimals), sr = success rate in % (1 decimal), passEpa/rushEpa = the same on pass/run plays only. Offense rank 1 = highest; defense rank 1 = lowest allowed.
- referees: every regular-season game in games.csv from 2023 through this season that has a referee and a final score. o/u/p compare total points with total_line; ppg = total points per game; homeWinPct = % of games the home team won.
- defVsPosition (how this team's defense does against a position, per game this team played):
  - rb = rushing yards and rushing TDs by RBs against this defense
  - recRb = receiving yards and TDs by RBs against this defense
  - te = receiving yards and TDs by TEs; wr = receiving yards and TDs by WRs
  - rank 1 = fewest yards/G allowed to that position; yds 1 decimal, td 2 decimals.
- nflverse passing yards are gross (before sack yardage), so team pass yds/G may run slightly higher than Pro-Football-Reference's net figures. That's expected; don't try to reconcile it.
- data/epa.json (the EPA page) is computed entirely by `scripts/epa_ratings.py` from the play-by-play file; see the README's EPA entry. Don't change its method in this task.
